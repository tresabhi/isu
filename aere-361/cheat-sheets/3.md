## Memory

- Speed: registers, cache (SRAM), memory (DRAM), disk, cloud
- Access row-wise not column-wise (C stores matrices row-major)
- The stack stores temporary variables declared within functions
  - It's a LIFO (last in, first out)
  - This is managed by the CPU so you don't have to manually allocate it
  - This has a limit that changes by the OS
- The heap is not managed fully managed by the CPU; you must do it
  - It's much larger than the stack and without hard limits
  - Use `malloc`, `calloc`, and `realloc` to allocate and `free` to free
  - It's a little slower than the stack and always accessed using pointers
- `size <FILENAME>` monitors memory usage (look at `bss` column)
- `calloc` also reservers memory, but accepts a count and element size
  - `SYMBOL = (<TYPE>*)calloc(<COUNT>, <ELEMENT SIZE>)`
  - It's slower than `malloc` since it fills the area with 0s
- `realloc` resizes a portion of the heap
- `memcpy`, `strcpy`, `strncpy`, `strcat`, and `strncat` help move memory around
- `ptr = (struct Point*) malloc(num * sizeof(struct Point))` casts the struct to `malloc`

## Caching

Fast allocation

```c
arr = (int **)malloc(r * sizeof(int *));
arr[0] = (int *)malloc(r * c * sizeof(int));
for(i = 0; i < r; i++) arr[i] = (*arr + c * i);
// table[row][col]
```

## IEEE-754

- Stored Exponent = actual exponent + bias
- Bias = $2^{n-1} - 1$
- `float`, `double`, `long double`
  - Decimal places: 6, 15, 19

| Precision | n    | Bias    | Formula                |
| --------- | ---- | ------- | ---------------------- |
| Half      | $5$  | $15$    | $2^4 - 1 = 16 - 1$     |
| Single    | $8$  | $127$   | $2^7 - 1 = 128 - 1$    |
| Double    | $11$ | $1023$  | $2^10 - 1 = 1024 - 1$  |
| Quad      | $15$ | $16383$ | $2^14 - 1 = 16384 - 1$ |

## GCC

- `-c` creates `.o` files
- `-std=c99 -pedantic -Wall -Werror` boosts warning verbosity
- `-g` enables gdb diagnostics
- `-I<PATH>` includes header files in that directory
- `-L<PATH>` states where to look for shared objects (`*.so`)
- `-l<NAME>` includes the specific object (like `m` for `libm.so`)
- `-fPIC` generates position independent code (for `*.so` files)
